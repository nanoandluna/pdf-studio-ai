# 0.4.1 项目整理记录

检查日期：2026-10-09。范围：当前主分支的代码、运行入口、文档和依赖，不包含商业级 PDF 编辑保真认证。

## 核心发现与处理

| 原问题 | 本次处理 |
|---|---|
| 保存后替换源字节，但页面索引/操作仍指向旧 PDF，第二次保存会重复应用编辑 | 始终保留打开时的源字节；保存使用操作快照；撤销/重做与保存状态关联 |
| pdf.js worker 转移 ArrayBuffer，保存引擎可能失去输入 | 给 pdf.js 独立副本 |
| 标注只在屏幕绘制，未写入保存 PDF | 移除原型与宣传，路线图注明重新引入标准 |
| 新版 Electron 没有 File.path，拖拽 fallback 却把文件名当磁盘路径 | 仅读取 File 字节；首次另存；不扩大任意磁盘路径权限 |
| 切换 Provider 共享旧 API Key，测试按钮可能测错服务 | 各 Provider 独立加密配置；只测试当前服务和实际输入 |
| 无效语言/质量设置、错误的关于版本、开发脚本含 TypeScript 语法 | 删除无效选项；版本使用 package.json；重写有效开发入口 |
| 退出没有未保存提醒，打开失败先销毁旧文档 | 退出/切换提醒；新文档加载成功后再释放旧文档；写盘采用临时文件替换 |
| AI 专用撤销可能撤销后续手动操作或把导出当成编辑 | 记录实际命令 ID，只有原命令仍在撤销栈顶部才允许一键撤销 |
| 历史冒烟只打印结果、CI 没检查启动脚本与实际桌面 | 统一真实 Electron 冒烟，断言渲染/保存/撤销/权限；补充脚本语法和打包检查 |
| 开源文档含历史环境与过度承诺 | 双语说明实际功能、贡献入口、发布流程和明确限制 |

## 验证范围

- Vitest 回归：连续保存、删除/排序/旋转组合、保存后撤销、保存失败/取消、写盘期间编辑、损坏 PDF、拖拽另存、Provider 密钥隔离、旧配置迁移和原子写入。
- TypeScript 和全部启动脚本语法检查。
- Windows 上真实 Electron + pdf.js 打开/渲染测试，连续保存到磁盘并用 pdf-lib 复读验证，保存后撤销恢复页面，未授权路径读取拒绝。
- Windows 便携版打包；第三方许可文本随包分发。
- 未使用真实收费 API Key 执行远程 AI 请求；OCR CDN/完全离线、复杂 PDF 保真以及 macOS/Linux 桌面行为仍需专项测试。

## 依赖审计

本次升级 Electron 33 → 44、electron-builder 25 → 26、Vitest 2 → 5，以及受影响的构建工具，并更新锁文件。完整 `npm audit` 公告从 38 项（含 3 项 critical）降到 15 项（5 high / 10 moderate）；`npm audit --omit=dev` 为 0。

剩余公告主要来自 Tailwind 3 与打包工具的传递依赖，需要继续处理。Electron 虽列在 devDependencies 中仍随安装包发布，不能将 production audit 为 0 解释为安装包全面无风险。Dependabot 会定期提出更新，路线图保留依赖维护任务。

## 后续

优先处理复杂 PDF 兼容性、OCR 本地资源与剩余工具链公告。标注应在能导出、撤销、旋转及重新打开后再回到产品界面；英文界面也应完成实际翻译后再提供切换。
